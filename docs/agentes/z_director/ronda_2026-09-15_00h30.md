# Informe del Director — Ronda 8 (2026-09-15)

## Mandato

Continuación ("continua") tras la ronda 7. Frentes propuestos: features de
cargo para dividir hive_base, migración `rlua→mlua`, test de roundtrip ML.

## Auditoría y decisiones

1. **`rlua` NO era una dependencia muerta** (corrección de la hipótesis
   inicial): la usa `beekeeper::scripting::LuaEngine` (66 líneas) para la
   consola Lua del TUI. Decisión: migrar a `mlua 0.10` (lua54, vendored) —
   crate mantenido, misma API semántica.
2. **CI ROTA** — hallazgo de máximo valor: `.github/workflows/ci.yml` tenía
   triggers malformados (`branches: aster]`) y seguía compilando `weaver`
   (eliminado en ronda 2). Consecuencia: **la CI no puede haber estado
   corriendo**; el badge verde del README era teatro. Decisión: reparación
   completa y modernización.
3. **Test de roundtrip ML**: la ronda 7 dejó el pipeline Python validado, pero
   el camino de PRODUCCIÓN (build.rs cifra → runtime descifra → `from_binary`
   → predict) no tenía cobertura. Decisión: test Rust en `worker` que ejercita
   el modelo embebido real, sin dependencias de Python en CI.
4. **Split de hive_base por features**: análisis vs beneficio — los 43 módulos
   restantes son todos load-bearing para los binarios de la colonia; portar
   transporte (tokio/reqwest/tungstenite) a feature obligaría a cada crate
   agente a opt-in, con churn alto y ganancia baja a esta escala. **Decisión:
   diferir** con análisis documentado en ROADMAP (revisit si crece hive_base o
   aparece target embebido).

## Prioridad de seguridad

El test de roundtrip destapó en la primera ejecución un bug real: un
`SIGABRT` por asignación de ~512 GB. El Director lo escaló como hallazgo de
seguridad (ver informe de Bugs/Seguridad): era una vulnerabilidad de
denegación de servicio por modelo corrupto en `from_binary`.
