## Resumen

La cirugía de eliminación (weaver + 4 módulos + ephemeral) destapó tres roturas latentes que habrían fallado en CI/builds de terceros. Todas corregidas y verificadas. Además, inventario actualizado de lo no corregido.

## Fixes aplicados

### Fix 1 — Build Windows de stinger roto

- **Descripción:** la rama `#[cfg(target_os = "windows")]` de `stinger/src/main.rs` llamaba `launch("weaver", embedded::WEAVER)` y definía `pub const WEAVER` con `include_bytes!(weaver.exe)` — referencias a una constante/archivo eliminados.
- **Severidad:** media (rompía `cargo build --target x86_64-pc-windows-gnu` del dropper; no visible en `cargo check` Linux porque el código está cfg-gated).
- **Causa raíz:** la eliminación del crate weaver no contemplaba los embeds condicionales del dropper.
- **Solución + archivos:** `stinger/src/main.rs` — constantes `WEAVER` (4 cfg-variants), `fileless_spawn("weaver", ...)` (Linux) y `launch("weaver", ...)` (Windows) eliminados; `stinger/build.rs` — bins de weaver fuera de las listas de embed y del mensaje de ayuda.
- **Cómo verificarlo:** `cargo check --workspace` (Linux) exit 0; consistencia estática confirmada (`rg WEAVER stinger/` sin resultados); el target Windows no es verificable en esta máquina (sin toolchain) — cobertura pendiente de CI.

### Fix 2 — YAML inválido en docker-compose.lab.yml

- **Descripción:** el servicio weaver contenía `networks: ive-net]` (sintaxis YAML rota, preexistente).
- **Severidad:** baja (rompía cualquier tooling que parseara el compose del lab).
- **Solución + archivos:** bloque eliminado junto con el servicio weaver (`docker/lab/docker-compose.lab.yml`); `docker-compose.yml` también limpiado.
- **Cómo verificarlo:** `python3 -c "import yaml; yaml.safe_load(...)"` → válido en ambos compose.

### Fix 3 — Builds/scripts referenciando `-p weaver`

- **Descripción:** `Dockerfile`, `hive.sh`, `scripts/*` construían con `-p weaver` o copiaban `target/release/weaver` → fallo garantizado de docker build y scripts tras eliminar el crate.
- **Severidad:** media (CI/CD roto para cualquier usuario que construya desde cero).
- **Solución + archivos:** todas las listas `-p` y COPY actualizadas (Dockerfile, hive.sh, launch_colony, deploy, build_payload, scenario, lab_setup, Dockerfile.lab).
- **Cómo verificarlo:** `bash -n` OK en los 8 scripts; `rg -i weaver` sin referencias de build activas.
